# Phase 11 — SEO (metadata, Open Graph, sitemap, robots, structured data)

Date: 2026-08-19

Covers roadmap item 11 / spec section 3.4, scoped to: site URL config +
`metadataBase`, root Open Graph/Twitter card metadata, per-page OG overrides
(shop + product), `robots.txt` + `sitemap.xml` (Next 16 MetadataRoute
conventions), and a `BreadcrumbList` JSON-LD on product pages. Nothing outside
that list was touched.

## A. Canonical site URL — `NEXT_PUBLIC_SITE_URL`

- Added `NEXT_PUBLIC_SITE_URL` to `.env.example` and `.env.local`
  (`http://localhost:3000`), **flagged** in both files as needing the real
  domain before launch.
- `src/lib/site.ts` (new) exports `SITE_URL`
  (`process.env.NEXT_PUBLIC_SITE_URL ?? "http://localhost:3000"`) plus
  `OG_IMAGE` — the logo fallback share image (`{url, width, height, alt}`).
- Root layout `metadata` now sets `metadataBase: new URL(SITE_URL)`, so every
  relative URL in metadata (og:image etc.) resolves to an absolute one.

## B. Root Open Graph + Twitter card

Root layout metadata adds:

- `openGraph`: `type: "website"`, `siteName: "Luce Bianca"`, `images: [OG_IMAGE]`
  (the logo, 1536×1024). `og:title` / `og:description` are derived from the
  root title/description automatically.
- `twitter`: `card: "summary_large_image"`, `images: [OG_IMAGE]`.

## C. Per-page OG/Twitter overrides

- **/shop**: `metadata` gained a matching `openGraph` (title, description,
  `url`, `siteName`, `images: [OG_IMAGE]`) and `twitter` block.
- **/product/[slug]** `generateMetadata`: `openGraph` + `twitter` using the
  product's **main image** (first `is_main` image, else first image) and
  **price** — the description is suffixed with `— From {price}` (fr-MA
  `formatPrice`, e.g. "From 39,99 MAD"); `og:url` points at the product page.
  Main-image handling was extracted into `productMainImage` /
  `productLowPrice` helpers shared with the page body (no duplicated logic).

### Next 16 gotcha — og:image does NOT inherit

When a child route defines its own `openGraph` object, Next does **not** merge
the layout's `openGraph.images` in (verified empirically: a product page with
no images rendered **no** og:image even though the layout had one). Fix: the
shop and product pages set `images: [OG_IMAGE]` explicitly as their fallback,
and products use their own Cloudinary image when present. The logo fallback is
therefore explicit on every page.

## D. robots.txt + sitemap.xml (Next 16 MetadataRoute conventions)

- **`src/app/robots.ts`**: `User-Agent: *`, `Allow: /`, `Disallow: /admin`,
  `/cart`, `/checkout`, `/order-confirmation`, `Sitemap: {SITE_URL}/sitemap.xml`.
- **`src/app/sitemap.ts`**: static entries for `/` and `/shop`, then one entry
  per active product at `/product/{slug}` with `lastModified` from the
  product's `updated_at`. The API caps `per_page` (default 12, max 100), so
  the sitemap **paginates through every page** (`meta.pages`) and dedupes by
  product id. If the API is unreachable it still emits the static entries
  rather than failing the route.

## E. Product page — BreadcrumbList JSON-LD

Added a second `application/ld+json` script (Home > Shop > product name),
using the same `JSON.stringify(...).replace(/</g, "\\u003c")` escaping pattern
as the existing Product JSON-LD, with `item` URLs resolved from `SITE_URL`.

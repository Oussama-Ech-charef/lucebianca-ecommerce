# Phase 2 — Numbered migrations + real register/login

Date: 2026-08-16 (local-only notes, matches the docs convention so far)

## A. Numbered migrations (spec section 4 closing note)

- `database/migrations/001_initial_schema.sql` — the original full schema,
  frozen. `database/schema.sql` kept as a fresh-setup snapshot reference.
- `database/migrations/002_add_refresh_tokens_table.sql` — new table added
  as a migration, NOT by editing `001` or `schema.sql`.
- `database/migrations/README.md` — documents the convention: append-only
  numbered files, `001` is the source of truth.

Decision: `refresh_tokens` (migration 002) — `id`, `user_id` (FK `users(id)`
`ON DELETE CASCADE`), `token_hash CHAR(64)` (SHA-256 hex of the refresh
token — the raw token is NEVER stored), `expires_at`, `created_at`,
`revoked_at` (nullable). Unique on `token_hash`, index on `user_id` (reused
by the FK). This makes logout/revocation possible in a later phase without an
API redesign; until then the stateless access JWT carries auth state.

## B. Real register / login (roadmap item 3)

Implemented in `App\Services\AuthService` + `App\Controllers\AuthController`:

- **Validation (server-side, spec 3.1):** new `App\Core\Validator` plus
  `ValidationException` (per-field errors → 422),
  `ConflictException` (→ 409), `InvalidCredentialsException` (→ 401).
- **Password rule decision:** minimum **8 characters**
  (`AuthService::MIN_PASSWORD_LENGTH`), enforced server-side on register.
  Spec fixes no number; 8 is a reasonable floor for this store. Hashing uses
  `password_hash($password, PASSWORD_DEFAULT)` (bcrypt on PHP 8.5).
- **Duplicate email:** 409 `{"error":"Email already registered."}` — simple
  message acceptable here (not a high-security app).
- **Login:** same generic 401 `{"error":"Invalid credentials."}` whether the
  email is unknown or the password is wrong (no field-level disclosure).
- **Tokens:** access JWT via `Auth::issue($id, 'user', $ttl)` (exp = iat +
  3600s from `JWT_TTL_SECONDS`); refresh token = 48 random bytes
  (`random_bytes(48)`) base64url-encoded (well above the 32-byte minimum),
  with only `hash('sha256', $token)` persisted via the new
  `App\Repositories\RefreshTokenRepository` (`create`, `findActive`,
  `revoke`). Login also issues/stores a refresh token. Google OAuth
  `/api/auth/google` is untouched (still a 501 stub — separate task).

New/changed files: `Core/Validator`, `Core/ValidationException`,
`Core/ConflictException`, `Core/InvalidCredentialsException`,
`Repositories/RefreshTokenRepository`, `Repositories/UserRepository`
(+`findById`), `Services/AuthService`, `Controllers/AuthController`.

## D. Follow-up: refresh-token rotation + logout revocation (same day)

Small follow-up that completes the token lifecycle — no schema/migration
change (the design from section A already anticipated it, no API redesign).

New/changed files: `routes.php` (+`/api/auth/refresh`,
`/api/auth/logout`, both public, no middleware), `Services/AuthService`
(+`refresh()`, `logout()`, private `hashToken()` helper reused by token
issuance), `Controllers/AuthController` (+`refresh()`, `logout()`),
`Core/Response` + `Controllers/Controller` (+`noContent()` for a real
empty 204), `Core/Validator` (label now renders `refresh_token` nicely).

Behaviour:

- **Rotation (`refresh()`)**: only the SHA-256 hash is compared
  (`findActive`). A valid token is revoked and immediately replaced —
  single-use, so a stolen token works at most once. On expiry/unknown/
  revoked → 401 `{"error":"Invalid or expired refresh token."}`. If the new
  pair fails to issue, the old token is restored so the client can retry.
- **Logout (`logout()`)**: revokes by hash. Idempotent — unknown or
  already-revoked tokens are a no-op and still return **204** (no body via
  `Response::noContent`), so repeat logouts never fail. The short-lived
  access JWT is left to expire on its own TTL (stateless).
- **Validation**: `refresh_token` required (non-empty) on both → 422
  `{"error":"Validation failed.","errors":{"refresh_token":"Refresh token is required."}}`,
  thrown from the service the same way register/login already do.

# Stack Detection Signals

Use these files as clues, then confirm the actual stack by reading configuration and source code. A dependency listing alone is not proof that a technology is used.

| Signal | Possible technology |
|---|---|
| `package.json` | Node.js, JavaScript, or TypeScript ecosystem |
| `tsconfig.json` | TypeScript |
| `vite.config.*` | Vite |
| `next.config.*` | Next.js |
| `composer.json` | PHP ecosystem, possibly Laravel or Symfony |
| `artisan` | Laravel |
| `requirements.txt`, `pyproject.toml` | Python |
| `manage.py` | Django |
| `Cargo.toml` | Rust |
| `go.mod` | Go |
| `pom.xml` | Java with Maven |
| `build.gradle` | Java/Kotlin with Gradle |
| `*.csproj` | .NET |
| `pubspec.yaml` | Flutter/Dart |
| `Gemfile` | Ruby |
| `mix.exs` | Elixir |
| `Package.swift` | Swift |
| `*.sln`, `*.fsproj` | .NET solutions or F# |
| `Podfile` | iOS dependency management |
| `android/`, `ios/` | Mobile project targets or cross-platform app structure |
| `pnpm-lock.yaml` | pnpm package manager |
| `yarn.lock` | Yarn package manager |
| `package-lock.json` | npm package manager |
| `Dockerfile` | Docker image build |
| `docker-compose.yml`, `compose.yml` | Container orchestration |
| Playwright configuration | Browser end-to-end testing |
| `phpunit.xml` | PHP testing |
| `pytest.ini`, `tox.ini` | Python testing |

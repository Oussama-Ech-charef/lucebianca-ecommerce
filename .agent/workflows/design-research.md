# Design Research Workflow

## Related Skills

`design-research` and `product-design`, with `frontend`, `web-design-guidelines`, `accessibility-internationalization`, `mobile`, or `agent-browser` when required.

## Planning Only

Use this workflow when the user wants design references, critique, a visual direction, or a plan before code changes.

1. Resolve the project and target surface.
2. Inspect the current UI, content, states, tokens, and constraints.
3. Choose the surface mode and the research question.
4. Gather a small, relevant set of real-product or authoritative references.
5. Record source URLs, retrieval dates, observed patterns, and limitations.
6. Extract principles instead of copying a visual identity.
7. Produce a Design Direction and Scope Gate.
8. Ask for confirmation before implementation or before adding an unapproved visual capability.

## Implementation Handoff

If implementation is approved, hand off:

- confirmed design decisions;
- proposed decisions accepted by the user;
- content and asset constraints;
- component and state inventory;
- responsive and accessibility requirements;
- verification plan and unverified items.

Do not modify files during planning-only requests. Do not treat inspiration references as project requirements.

# Architecture

Analyze boundaries, responsibilities, data flow, dependencies, failure modes, testability, performance, and deployment context.

Choose the simplest architecture that can satisfy the confirmed requirements. Depending on the project, consider layered architecture, a modular monolith, MVC, services, repositories, event-driven boundaries, hexagonal or clean architecture, and component-based UI.

## Output

Describe the current or proposed boundaries, key responsibilities, data flow, dependency direction, trade-offs, risks, and verification approach.

Do not introduce layers, services, patterns, or abstractions without a concrete reason.

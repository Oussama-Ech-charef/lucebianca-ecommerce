# Design Research

Use this skill before a substantial UI design, redesign, visual direction, or design-to-code task when the project needs grounded references.

## Goals

- Understand the product, users, task, content, and surface mode before choosing a visual direction.
- Study real shipped interfaces and interaction patterns rather than isolated visual trends.
- Extract principles and reusable decisions without copying another product's identity.
- Produce a design direction that is specific, explainable, accessible, responsive, and testable.

## Reference Sources

Use sources according to the question:

- Real product screens and states: Mobbin, Refero, or an equivalent trusted product-reference library.
- Complete interaction flows: Page Flows or an equivalent flow reference.
- Marketing and visual composition: Land-book, Awwwards, or an equivalent curated gallery.
- Usability and accessibility principles: Nielsen Norman Group, W3C, or the project's adopted design system.

Do not treat a gallery screenshot as evidence that an interaction is usable. Record the source URL, retrieval date, surface/pattern, and what was actually observed. If web access is unavailable, state that limitation and use project evidence or user-provided references instead.

## Method

1. Inspect the current project UI, design tokens, content, routes, states, and constraints.
2. Identify the surface mode: persuade, operate, read, or experience.
3. Search for references by task and state, not only by visual style.
4. Capture a small set of relevant references and record the pattern each one demonstrates.
5. Extract transferable principles: hierarchy, density, navigation, feedback, typography, spacing, color, motion, and state handling.
6. Define what to preserve, what to change, and what is explicitly out of scope.
7. Mark every design choice as confirmed project evidence, proposed direction, assumption, open question, or recommendation.
8. Produce a Design Direction before implementation.

## Anti-Generic Design Gate

Before implementation, reject designs that rely on ungrounded defaults such as arbitrary gradients, excessive glassmorphism, identical rounded cards, decorative dashboards, random neon accents, generic hero copy, or invented visual trends.

Require at least one project-specific reason for each major choice of layout, type, color, density, imagery, motion, and component behavior. Prefer real content, meaningful states, deliberate hierarchy, and a small coherent visual system.

## Output

Return:

- Reference log with URLs, dates, patterns, and observations.
- Current UI evidence and constraints.
- Visual direction and design principles.
- Typography, color, spacing, shape, icon, motion, and imagery direction.
- Component and state rules.
- Responsive and accessibility requirements.
- Anti-patterns to avoid.
- Confirmed facts, proposed decisions, assumptions, open questions, and recommendations.
- Scope gate and next-step confirmation before implementation.
